# AI Booster Kit V1 Roadmap

This is the ordered execution view derived from the [Vision Contract](../../VISION.md).
It does not own current branch, pull-request, test, or delivery facts, and it
does not authorize a milestone's execution. Read
[current delivery state](current-state.md) for the live route.

## Ordered milestones

### 1. Foundation Reset

Establish the canonical vision, domain, context, router, Claude projection,
ADR, engineering-skill configuration, migration record, and documentation
checks. Exit evidence is one reviewable local documentation diff with passing
link and whitespace checks.

### 2. Standalone Plan Proof

Run one real planning module under the authority model and produce a plan a
fresh reviewer can inspect. Exit evidence is the plan, its acceptance boundary,
and its stated verification approach.

### 3. Standalone Review/Test Proof

Run one real review or test module and produce proportionate, reviewable
evidence. Exit evidence is the inspected artifact, the executed check or
explicit non-execution state, and the reviewer-facing result.

### 4. Safe Stop Proof

Run one real task that correctly ends as `STOPPED` or `UNKNOWN`. Exit evidence
is the reason, preserved facts, authority or evidence boundary, and next safe
action.

### 5. End-to-End Change Proof

Run one real change-producing task through clarification, context, plan,
implementation, verification, and handoff without an unapproved external
write. Exit evidence is the reviewable artifact chain and its proportional
checks.

### 6. V1 Completion Review

A reviewer checks all four required proofs against `VISION.md`. Exit evidence
is an explicit `READY` or `NOT READY` verdict with any missing proof named;
the review never promotes a gap to completion for convenience.

## Roadmap rule

A milestone becomes executable only through its own bounded design, accepted
plan, and fresh authority. Historical platform plans and earlier roadmaps
remain evidence, not default routing.
